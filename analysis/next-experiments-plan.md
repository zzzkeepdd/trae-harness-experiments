# 下一步实验计划

> **实测模型**: deepseek-v4-pro（所有实验只跑这一个模型）
> **框架**: trae-harness v1.3
> **实验方法**: 纯 A/B 对照 = DSV4 Pro 直出 vs DSV4 Pro + Harness 全流程

---

## 一、实验定位：我们不比他们测过的，我们测他们没测过的

现有公开基准（HumanEval、SWE-bench、LiveCodeBench）测的都是：

| 基准 | 测什么 | 跟我们实验有关吗？ |
|------|--------|:--:|
| HumanEval | 函数级补全（填空） | ❌ 完全不相关 |
| SWE-bench | 修已有代码库的 bug | ❌ 完全不相关 |
| LiveCodeBench | 竞赛编程题 | ❌ 完全不相关 |

我们测的是：**从零做完整需求 → 写工程代码 → 写测试 → 通过全部质量门 → 交付**。这是一个新赛道。

御三家纸面数据仅作背景参考——不用于直接对比，因为维度完全不同。

### 背景：DSV4 Pro 在公开基准上的位置

| 基准 | Claude Opus 4.7 | GPT-5.5 | Gemini 3.1 Pro | DeepSeek V4 Pro |
|------|:----:|:----:|:----:|:----:|
| HumanEval | ~92% | **~94%** | ~90% | 87.6% |
| SWE-bench Verified | **87.6%** | ~85%* | 80.6% | 83.7% |
| LiveCodeBench | ~90* | ~91.7* | ~89.2* | **93.5** |
| Codeforces Rating | - | 3168 | 3052 | **3206** |

> DSV4 Pro 在竞赛编程上领先，工程实战（SWE-bench）上略落后——但这些基准与我们实验测的不是同一回事。

## 二、已完成的实验 & 已验证的能力

| # | 实验 | 验证的能力 | 结果 |
|:--:|------|----------|------|
| v1 | A/B 原始对照 | 辩论产出统计 | 方法论缺陷，数据无效（已废弃） |
| v2 | 独立测试驱动 | 代码正确性、边界处理、安全防护 | A=92% B=99% Δ=+6% |
| v3 | 编排器强制执行 | 流程完整性 (15步)、质量门全激活 | A=90% B=100% Δ=+10% |

**当前结论**: Harness 将 DSV4 Pro 的工程代码通过率从 90% 提升到 100%（+10%），消灭 4 个真实 bug。

## 三、待验证的能力 + 实验设计

### v4: 测试质量实验（P0 — 最能体现工程价值）

**验证 DSV4 Pro 的能力**: 写出有效测试的能力  
**验证 Harness 的效果**: C27 测试闸门 + C32 有效断言 → 测试是否更有效？

```
A 组: DSV4 Pro 直出代码 + 直出测试
B 组: DSV4 Pro + Harness 全流程（C27 强制写 test_*.py + C32 有效断言检查）
```

| 指标 | 工具 | 说明 |
|------|------|------|
| 测试覆盖率 | coverage.py branch coverage | 覆盖了多少分支 |
| Mutation Score | mutmut / mutpy | 注入变异后测试能否检出（真正的测试质量） |
| 断言密度 | 有效断言数 / 函数数 | 测试写得有多认真 |
| 测试通过率 | 直接跑测试 | 基本正确性 |

**预期**: B 组 mutation score 比 A 组高 15~25%。

**为什么这很重要**: 公开基准只测"代码对不对"，不测"测试写得好不好"。mutation score 是工程界公认的测试质量金标准——但无一商用模型公开过此数据。

---

### v5: 代码规范实验（P1）

**验证 DSV4 Pro 的能力**: 写出规范代码的能力  
**验证 Harness 的效果**: MODULE_2_STEP_2 Code QA 真实执行 → 规范等级提升？

```
A 组: DSV4 Pro 直出代码
B 组: DSV4 Pro + Harness（MODULE_2_STEP_2 Code QA 实际运行 flake8+pylint）
```

| 指标 | 工具 |
|------|------|
| flake8 违规数 | flake8 |
| pylint 评分 | pylint |
| 可维护性指数 | radon MI |
| 圈复杂度 | radon cc |

**预期**: B 组 flake8 违规减少 30~50%，pylint 评分提升 2~3 分。

---

### v6: 安全加固实验（P1）

**验证 DSV4 Pro 的能力**: 从零安全设计的意识  
**验证 Harness 的效果**: 辩论能否发现安全漏洞？

在原有 6 个任务基础上新增 2 个安全专项：

| 新任务 | 安全场景 | 级别 |
|--------|----------|:--:|
| SQL 注入防护 | 输入过滤、参数化查询 | L3 |
| 文件上传安全 | 路径穿越、类型校验 | L3 |

| 指标 | 说明 |
|------|------|
| 安全用例通过率 | 预定义攻击向量是否被防御 |
| CWE 覆盖数 | 覆盖了多少种常见弱点类型 |

**预期**: A 组在 SQL 注入/文件上传上大概率有漏洞，B 组通过辩论攻击发现并修复。

---

### v7: Module 3 长期学习实验（P1 — Harness 独有）

**验证**: Harness 能否让 DSV4 Pro 越用越好？（同类错误不再犯）

```
第 1 轮: 6 个任务 → 产出宪法草案（C34-C36）
第 2 轮: 同样 6 个任务 + 2 个新任务 → 宪法版本号递增
第 3 轮: 继续累积
```

| 指标 | 说明 |
|------|------|
| 同类 bug 复发率 | 第 1 轮出现的 bug 在第 2、3 轮是否还出现 |
| 宪法规则命中数 | 每轮被触发执行的规则数 |
| 质量边际增速 | 测试通过率的轮次间提升 |

**这是 Harness 独有的能力** —— 没有任何其他框架能做到"一个模型被同一个框架多次使用后产出质量自动提升"。

---

### v8: 性能意识实验（P2）

**验证 DSV4 Pro 的能力**: 算法复杂度意识  
**验证 Harness 的效果**: 辩论中性能维度攻击 → 是否触发优化？

```
给定 O(n²) 实现的任务 → B 组辩论中性能维度攻击 → 看是否优化为 O(n) 或 O(n log n)
```

| 指标 | 说明 |
|------|------|
| 时间复杂度变化 | 静态分析 |
| Runtime benchmark | 实际跑 1000/10000 规模对比 |

## 六、核心叙事

> 现有 AI 编程基准（HumanEval / SWE-bench）测的是"填空"和"修 bug"——而真实软件工程是"从零做需求"。我们在这个新赛道上进行了 A/B 对照实验：DSV4 Pro 直出代码通过率 90%，加上 Harness 全流程后达到 100%(+10%)。下一步实验将首次量化 DSV4 Pro 在测试质量、代码规范、安全设计、长期学习等维度的表现——这些维度现有公开基准从未覆盖。
