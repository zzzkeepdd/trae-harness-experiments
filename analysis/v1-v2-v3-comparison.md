## 方法演进教训

### v1 → v2
- **教训**: 不可用 Harness 自身审计器评估对照组——循环推理。必须用独立测试套件。
- **改进**: v2 引入独立 TestResult 框架，每个任务有预定义的 boundary/normal/edge 用例。

### v2 → v3
- **教训**: 流程定义的 15 个步骤中只有 2 步被执行（开发+审计），质量门形同虚设。
- **改进**: v3 编排器将 15 步状态机内联到实验脚本，每步检查文件存在后才能前进。

### v3 → v4 (Next)
- **待改进**: C32 堵 `assert True` 漏洞；C31 纳入 Module 3；引入 mutation score/flake8 评分。
