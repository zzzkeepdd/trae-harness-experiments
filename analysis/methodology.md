# 实验方法论

## 核心原则

1. **独立评估**: 评估手段必须独立于被测系统。不可用 Harness 审计器检查无 Harness 代码。
2. **同模型对比**: A/B 两组使用同一模型，差异纯粹来自流程干预。
3. **可复现**: 每个实验锁定 Harness 版本，结果 directory 包含完整原始数据。

## A/B 实验设计

```
                    ┌─ 对照组 (A) ── 模型直出代码 ── 独立测试 ──┐
任务定义 ── 同一模型 ─┤                                          ├── 对比
                    └─ 实验组 (B) ── Harness全流程 ── 独立测试 ──┘
```

## 任务分级

| 级别 | 判据 | 任务数 |
|:---:|------|:--:|
| L1 | ≤3 文件、单一技术栈、无外部依赖 | 2 |
| L2 | 4-15 文件、1-2 外部依赖 | 2 |
| L3 | >15 文件或 ≥3 API 或复杂并发/权限 | 2 |

## 评估指标

| 指标 | 定义 | 用途 |
|------|------|------|
| **测试通过率** | 独立测试套件 pass/(pass+fail) | 代码质量量化 |
| **管线通过率** | 编排器通过的步骤/总步骤 | 流程完整性 |
| **质量差值** | B 组通过率 - A 组通过率 | Harness 效果 |
| **bug 数** | 独立测试中捕获的失败用例 | 缺陷量化 |

## 独立测试套件设计

每个任务有预定义的 TestResult 用例，覆盖：

- **normal**: 典型输入正确输出
- **boundary**: 空值/None/边界条件
- **security**: 安全攻击向量（如 JWT none attack）
- **edge**: 时序/并发/竞态条件

测试用例写死在 experiment 脚本中，不依赖 Harness 产出。

## 实验环境

- **模型**: deepseek-v4-pro
- **Python**: 3.12
- **系统**: Windows, 64-bit
- **Harness 框架**: [trae-harness](https://github.com/zzzkeepdd/trae-harness)
