# v1: 原始 A/B 对照实验

> **Harness 版本**: v1.1 | **模型**: deepseek-v4-pro

## 实验设计

对照组(A) 模型直出代码 vs 实验组(B) Harness 多 Agent 辩论流程产出代码。

## 评估方法

使用 `harness_auditor.py` 检查文件存在性 → **方法论缺陷（循环推理）**。

## 结果

| | A 组 | B 组 |
|------|:--:|:--:|
| audit pass | 0/6 (0%) | 6/6 (100%) |

B 组辩论产出 24 个攻击点，21 个 ≥3 分。

## 经验教训

- ❌ 不可用 Harness 审计器评估对照组——评估工具必须独立于被测系统
- ❌ audit_pass 基于"文件是否存在"而非"代码是否正确"
- ✅ 辩论机制确实能发现代码中的边界/安全问题
- ✅ 复杂任务(L3)的辩论产出比简单任务更有价值
